Attendance

Padma uploads the biometric "Daily Attendance Report" (.xls) every few days. The app reads both companies in the file, maps device codes to staff, and works out each day: 8 h or more is Present, 6–8 h is Short (present, flagged for Ramesh to talk to the person), under 6 h is Absent, and a missing out-punch is Incomplete until someone fixes it. Every manual change goes through the change-with-reason sheet and leaves an audit row. Data in these screens runs up to Sat 21 Nov. Today, Mon 23 Nov, Padma uploads 16–22 Nov.

03-03

Upload, step 2: what's in the file

A dry run. The file is read and compared with what the app already has; nothing changes until Save import.

  • Dates found and both companies (RRL SONS + Default) with row and code counts, so a half-exported file is obvious.
  • Match opens device-code matching (03-04). Saving without matching is allowed; those punches wait in the unmatched queue.
  • Incomplete opens the fix list (03-05) after saving.
  • See 14 changed days opens a sheet: per day, old status → new status from the file. Days edited by hand are locked and never overwritten.
  • Save import: toast, then back to 03-01 on the newest day. Every import is logged (file, dates, who, when).
Open question: if the newest day in a file has almost no out-punches (file taken mid-day), should the app refuse that day or import it as Incomplete? Proposed: warn and skip that day by default.

03-04

Match device codes (one-time setup)

The device holds about 163 codes for 83 people: old codes 1–85 with full names, new codes 103–218 with short names, and 14 fingerprints with no name at all. This screen links each code to a VSM number once; after that, uploads only ask about new codes (3 today).

  • Confirm links the suggested employee and moves the counter (toast). Change and Pick open the staff picker sheet, which lists staff with no punches first.
  • Add as 2nd: an employee can have more than one code, so old enrolments still count if someone uses them.
  • Ignore hides a code; its punches never count. Undo from the Ignored chip.
  • A manual pick needs a short reason ("How do you know?") and is audit-logged. Name matches are logged without one.
  • Shown here mid-way through the first upload. The same list lives under Staff → Device codes (screen group 02).
For the owner: the cleanest fix is at the device (one code per person, ideally equal to the VSM number). The app copes either way.

03-05

Fix punches (incomplete days)

Every day with an in-punch but no out-punch, grouped by date, newest first. Pay day can't be finalised for a period that still has items here.

  • Out-time opens a sheet with the time (defaults to 21:00, shift end), the hours it gives and the status that follows, plus a reason.
  • Present opens the reason sheet with "Outside work" picked and 8 h credited (full sheet: 03-10).
  • Absent opens the reason sheet with a pay warning and a red button.
  • On save: toast, the row leaves the list, the day gets the "edited" mark and an audit row (who, when, old → new, reason).
  • Select (top right): tick several rows and give them one out-time and one reason.
Open question: in the sample file about half the staff skip the out-punch every day. Is a bulk "everyone out at 21:00, forgot to punch" acceptable, or must each day be checked? Proposed: bulk allowed, still one audit row per day.

Day detail (one employee, one day)

Answers "why does the app say this?" for any day: the raw punch text from the file, the device code, how hours were counted, which rule applied, and every change since.

  • ‹ / › step through this person's days.

03-10

Change day status (override with reason)

The kit's shared override sheet (D-02), set up for attendance. Opened here from Fix punches; the same sheet opens from the day detail, the month grid and the register.

  • Top card: what the machine gave, then old → new status, updated as you pick.
  • New status: Present, Short, Absent or Leave. Present credits 8 h; Leave uses this month's free leave (warns if none left).
  • Reason presets: Outside work, Machine fault, Forgot to punch, Other. "Forgot to punch" swaps in an out-time field so real hours are recorded. "Other" makes Details required; Save stays disabled until it's filled.
  • Save: toast, row leaves Fix punches, day marked "edited", audit row written (who, when, old → new, reason).
Open question: is a preset alone enough as the reason (e.g. just "Outside work"), or should Details always be required? Proposed: preset alone is enough, except Other.
