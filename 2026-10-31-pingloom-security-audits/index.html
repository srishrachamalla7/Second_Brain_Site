1. Firebase security rules audit

Tool: Google's firebase-security-rules-auditor skill.

Like I'm 5This check looks at the locks on Firebase databases and file storage. PingLoom doesn't keep anything in Firebase. It only uses Firebase to send phone notifications and crash reports. So there was no database lock to check, and the score is 5 out of 5. We still added locks in case someone switches a database on by mistake.

Score: 5 / 5 (secure). No Firestore, Cloud Storage or Realtime Database is used. Event data lives in PingLoom's own database, behind its access checks.

Lock rules for unused Firebase databases fixed

If a database were switched on later in "test mode", anyone could read and write it for 30 days. We added deny-all rules for Firestore, Storage and Realtime Database to the code (infra/firebase/), with steps for using them.

The server's Firebase key had more power than it needs fixed in the guide

The setup guide used Firebase's default admin key, which can change the whole project if it leaks. The guide now creates a separate key that can only send notifications.

Limit the Android app key owner step later

The app's Firebase key is not secret, but it should be limited to the PingLoom Android app in Google Cloud. This happens when the Firebase project is created.

2. Code security audit

Tool: Cloudflare's security-audit skill, quick mode, 10 helper agents, reading code only (no code was run).

Like I'm 5Helpers read the code looking for ways one person could get into someone else's account or data. They checked 14 areas and found nothing wrong there. They found 3 smaller weak spots. Because nothing could be safely run on this computer, the strict rules of this tool don't let it call anything "confirmed". We read the code ourselves and fixed all 3.

Weak spots

Connecting GitHub or Google to an account real · fixed

What: the "connect your GitHub or Google account" step was not tied to the person and browser that started it. A provider account could end up connected to the wrong PingLoom account.

Fixed: the step now needs a secret held by the browser or app that started it, and it is finished by the same signed-in user. Same protection the sign-in flow already has.

Email sign-in links on the phone fixed

What: when the app is signed out, opening an email sign-in link signs straight into that link's account, without showing which account.

Fixed: the app (and website) shows "Sign in as a***@example.com?" and waits for a tap first. It never silently replaces an account that is already signed in.

Votes from people who left the team fixed

What: if someone approved a decision and was then removed or demoted, their approval still counted toward the number of approvals needed.

Fixed: only votes from current members who are still allowed to decide count. Old votes stay in the history, marked as no longer counting.
