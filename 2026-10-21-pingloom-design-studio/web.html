The path to a first alert.

Target: under five minutes after sign-in. Measure it with new pilot users; do not present the target as a guarantee.

1. Create workspaceName the team boundary; create the first project and general channel.
2. Connect phoneInstall Android, sign in, allow notifications and confirm device registration.
3. Create server keyShow plaintext once, with a copy affordance and server-only warning.
4. Send test eventUse the authenticated dashboard route without exposing a server key in client code.
5. Inspect the resultSeparate API acceptance, provider acceptance, read and acknowledgement.

Every web page, planned.

The catalogue includes public, authentication, MVP and paid-beta routes. Route names are proposed UI paths; they are not live app endpoints.

Permissions shape the interface.

Enforce these rules on the server. Hiding a control is helpful UX, not an authorization boundary.
