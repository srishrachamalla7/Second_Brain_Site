05 / Notifications & attention

Be useful.
Earn the interruption.

A notification is an invitation to inspect an event. Design the interruption, the inbox item and the shared response together—without pretending that provider acceptance proves device display.

Try the notification lab.

Change priority, preview privacy and permission. This browser preview never asks for OS permission or sends a push.

Privacy is the default.

Minimal title and event reference on the lock screen. Fetch the full event after authentication. The explicit body-preview setting here is a design example, not permission to include real secrets.

High priority does not bypass Focus, OS restrictions or a user's preferences. Quiet hours and opt-in urgent routing are P1 designs.

A precise status vocabulary.

Transport progress, personal reading and shared acknowledgement are separate signals. Do not collapse them into one “delivered” badge.

Accepted

The database committed the event and outbox job. The API can now return 202.

Queued

The event is waiting for a worker to resolve eligible recipients.

Provider accepted

FCM accepted the push request. The phone may still be delayed or suppress display.

Retrying / Failed

A transient error will retry with backoff, or the attempt limit has ended. Keep error details safe and actionable.

Human signals stay separate.

01

Seen

Per user. Opening or explicitly marking an event read updates that user’s view.

02

Acknowledged

One shared record per event. The first authorized person and timestamp are visible to the team.

Per-device provider attempts may differ. Event detail should show those attempts rather than imply every recipient received a banner.

Priority is a promise of intent.

The user and operating system retain control of interruptions. Priority should also appear in text and accessibility labels.

Routing, in the right order.

A project channel is a team topic. An Android notification channel is an OS control for how interruptions behave. They solve different problems.

01

Authorize & validate

Check project key, channel, payload limits, request identity, quota and rate limits. An unauthorized or invalid event is never billed.

02

Store & resolve

Commit event plus outbox together. Route to authorized, opted-in subscribers, then create one attempt record per active device.

03

Send & recover

Submit minimal push data, record provider response, retry transient failures and disable permanently invalid tokens.

Design the exceptions.

These states have planned copy and a recovery path.

Permission denied

“Notifications are off. Your inbox still works.” Offer a settings action without blocking the inbox.

P0 · ANDROID

No active device

“This event was saved. No eligible devices were available.” Link to device setup for authorized users.

P0 · CONSOLE

Quota reached

“Monthly event limit reached.” Show the reset period and an owner/admin contact; rate limits have separate copy.

P0 · INGEST

Quiet hours

“Paused by your schedule.” Apply an urgent exception only when the user explicitly opted in.

P1 · PLANNED

Invalid device token

“This device needs to reconnect.” Disable the bad association and offer registration recovery.

P0 · DEVICE

Future iOS delivery

Respect permission, Focus, preview settings and APNs behavior. Do not promise time-sensitive bypass or critical alerts.
