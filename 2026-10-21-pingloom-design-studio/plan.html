Build in connected milestones.

Use the PRD’s acceptance gates. A UI demo, mock provider or screenshot does not complete a production feature.

M0

Architecture & runnable foundation

Monorepo, isolated Compose, migrations, provider interfaces, contracts, docs and CI.

Acceptance gateFresh checkout starts services; health and migration checks pass.
M1

Identity, workspace & setup

Verified accounts, rotated sessions, memberships, projects, channels and one-time API keys.

Acceptance gateTwo known-ID test accounts cannot access each other’s data; revoked keys fail.
M2

Durable ingest & routing

PostgreSQL event/outbox transaction, scoped idempotency, exact metering, workers and FCM attempts.

Acceptance gateAccepted events survive restarts; retries do not duplicate events or usage.
M3

Android & real-device push

Permission onboarding, token sync, inbox, detail, safe links, read and shared acknowledgement.

Acceptance gateA real handset receives real FCM push, opens the right event and acknowledges it.
M4

Dashboard & hardening

Complete setup flow, explorer, status, usage, errors, observability and privacy-safe logs.

Acceptance gateNew developer completes first alert; accessibility and security checks pass.
M5

Paid beta & teams

Invitations, secure sources, quiet hours, retention and verified hosted billing.

Acceptance gateUpgrade/cancel/replay lifecycle updates entitlements once from verified state.
Later

iOS concept → implementation decision

Separate Apple platform transport, navigation, privacy, publisher and device validation work.

Acceptance gateApproved scope, APNs path, physical-device evidence and policy review.
M6

Embedded SDK beta / Product B

Customer app recipients, Firebase delegation and distinct per-device metering.

Acceptance gateSeparate approval plus at least two SDK design partners.

What this review includes.

Seven smaller-model specialist contributions were synthesized into this shared design system. They ran in batches to fit available concurrency.
