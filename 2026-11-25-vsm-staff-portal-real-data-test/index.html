Everything was done through the app: employee import, biometric upload, device-code matching, salary upload, batch import, swap, punch fixes, pay run, advance. The core flows work on real data. The pay run for 1–15 Nov (pay date Sat 28 Nov) was created and calculated: earned ₹4,30,000, absence cuts −₹1,96,350 (510 unpaid days across 72 staff), TEST advance recovery −₹2,000, net ₹2,31,650. As expected, it is blocked by 293 days with no out-punch, so "Mark reviewed" stays disabled and it could not be finalised. Payslips (A4 and 80 mm) and payouts in the ledger could not be tested for that reason.

The API logged one server error (500) during the whole session (bug 1). There were no other server errors and no JavaScript errors. The other console messages were the expected 401 before login, expected 403s from deliberate clerk access checks, two 400s from the payslip log page (bug 8) and React Router upgrade warnings.

Bugs found

Nothing was changed in the code. Severity: Medium = wrong data or an error a user will hit. Low = cosmetic, or a small inconsistency.

1. Sundays page: server error on first open Medium

Where
backend/app/services/sundays.py ensure_months() (line 317), called from GET handlers (calendar.employee_calendar line 64, sundays.py lines 433, 446, 576).
Steps
Fresh database, open More > Sundays & batches.
Expected
Both requests return 200.
Actual
GET /api/sundays/batches returns 500: UniqueViolation ix_sunday_schedule_sunday (2026-11-01). The calendar and batches requests both lazily insert the same schedule rows at the same time. A reload fixes it. This can happen again whenever a new month enters the schedule horizon.

2. Off Sundays shown as "Absent" in attendance views Medium

Where
backend/app/services/attendance.py around line 101: off is set only when all codes report WeeklyOff. The attendance views also ignore the Sunday roster (calendar.sunday_off).
Steps
Staff > MATURI MOUNIKA (TEST batch B) > Attendance. Sun 15 Nov (batch C on duty).
Expected
Off.
Actual
Absent. Her old code 109 says WeeklyOff, but her new code 76 says Absent. Most staff have two codes, so the month view's Absent counts are inflated. Payroll and leave use the Sunday calendar correctly, so pay is not affected.

3. Employee leave history shows months before go-live Medium

Where
backend/app/routers/leave.py employee_view (lines 158–176). It always walks back 12 months and stops only at joining_date, which is empty for every imported employee.
Steps
Staff > any employee > Leave.
Expected
History starts at the first month with data (or go-live).
Actual
Dec 2025 – Oct 2026 each show "Unused · not decided yet, bank 0 → 1". November then opens with a bank of 0, which contradicts October's closing 1. The owner could be asked to decide on 11 phantom months per person.

4. Employee with no attendance data gets full pay without a block Medium (risk)

Where
Pay run calculation (backend/app/services/payroll.py). "nodata" days are not deducted and only raise a non-blocking warning.
Steps
Pay run 1–15 Nov, VANAMALA MADHU (VSM/086, no device code, 13 no-data days).
Expected
Blocked, or a prominent warning that this person has no attendance at all.
Actual
Line reads "no changes · ₹5,000". The only sign is one entry inside the collapsed "Other warnings (32)".

6. Rounding of the daily rate Low

Where
Pay run line maths.
Detail
The daily rate is rounded to ₹385 (10,000 ÷ 26 = 384.6), but period pay is exact (₹5,000 for 13 of 26 days). A person absent 12 of 13 days with 1 free leave day nets ₹380, not ₹385 (KOTA SWATHI, VSM/004, VSM/010). If all 13 days were unpaid the cut would be ₹5,005, more than the ₹5,000 earned. Not checked whether the result is clamped at zero.

Data findings (not app bugs)

  • Out-punches are mostly missing. Of 757 code-days with an in-punch, only 269 have an out-punch. Many staff (for example VSM/001, VSM/003, VSM/005, VSM/006) punch in every day but never out. This is why 53 people are blocked in the pay run.
  • 29 of 86 employees never punched under any matched code between 2 and 19 Nov (for example VSM/004, VSM/010 are absent all 13 working days in the pay run). On weekdays about 45–56 people punch. They may have left, or may punch under one of the unmatched codes.
  • 22 unmatched codes, 12 of them with punches (about 100 days in total): 101, 131, 146 (no name, 16 / 10 / 12 days), 110 "A ANITHA" (11), 165 "A BALU" (13), 174 "GOPI CHAND" (9), 212 "KEERTHANA" (14), 132 "G VASANTHA" (2), 187 (6), 200 (5), 121 "P RAJU" (1), 230 (1).
  • VSM/086 VANAMALA MADHU has no device code at all.
  • The device holds most staff twice: new codes 1–86 (matching VSM IDs, few punches yet) and older 1xx/2xx codes that carry most of the punches. Both are mapped, and punches are merged per day.
  • The employee file has 86 real rows, not 83, and no department column. Departments exist on the device (MENS WEAR, SYNTHETICS, and so on).
  • Sunday 8 Nov: 30 people punched. Sunday 15 Nov: only 5. Compare these with the real batch lists once you have them.
